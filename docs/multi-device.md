# 多设备元数据

两台设备各自运行 Nextcloud、OpenList 和适配器。
各设备的适配器连接百度上的同一个物理目录。

## 共享内容

控制目录名为 `.baidulibrary`，位于 `METADATA_DAV_PATH` 指定的目录内：

```text
.baidulibrary/
  format.json
  base-<标识>.json.gz
  events/<逻辑时钟>-<设备标识>-<操作标识>.json
```

初始快照包含已登记空文件的标记和逻辑修改时间。
操作记录包含后续写入、复制、移动、删除及修改时间变更。
路径相对于共享目录保存。各设备可以使用不同的 WebDAV 路径前缀。

各设备保留自己的数据库、上传暂存、凭据和恢复记录。
Git 仓库保存代码和通用配置。

## 首次发布

1. 在已有设备备份适配器状态目录。
2. 确认本机上传和命名空间恢复记录已处理完成。
3. 执行 `PublishMetadata`。
4. 等待命令报告成功。
5. 在新设备执行 `ConfigureStorage`。

首份发布由一台设备完成。后续设备读取同一个库标识。

## 变更传递

1. 设备先持久化本机发件记录。
2. 适配器上传操作意图，并读回确认。
3. 适配器执行文件操作。
4. 适配器上传元数据结果，并读回确认。
5. 适配器向客户端返回最终响应。

操作记录使用独立文件名。
各设备按逻辑时钟、设备标识和操作标识的顺序重放。
晚到记录会触发按序重放。
已确认的重放进度与数据库变更一起提交。
重启时复用本机进度和不可变快照缓存。

访问文件时，适配器最多每五秒检查一次操作目录。
实际可见时间还受 OpenList 和百度目录缓存影响。
`RefreshMetadata` 主动重新读取快照和操作记录。
客户端的目录发现周期另计。

## 故障处理

如果远端元数据读写失败，相关请求会报告服务错误。
本机发件记录继续保留。
连接恢复后，原设备补发记录。

如果其他设备看到了待完成操作，重叠路径会等待恢复。
在原设备恢复服务并重试文件操作，再执行 `RefreshMetadata`。

需要备份时，成套保留各设备的适配器状态目录和百度控制目录。
将 `.baidulibrary` 作为工具数据维护。

## 一致性边界

共享机制提供最终一致的逻辑元数据。
每次读取已登记空文件时，适配器仍然校验真实标记内容。

百度 WebDAV 的目录可见性和文件操作由上游提供。
同时写入同一个文件仍可能产生内容冲突。
优先让两台设备操作不同文件；按客户端提示处理同文件冲突。

云端操作记录持续保留。定期检查其数量和占用空间。
当前版本通过备份和保留记录维持恢复能力。
