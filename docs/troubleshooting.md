# 故障处理

先执行 `Status`。再检查运行目录中的 `logs/startup.log`。

| 现象 | 检查项 | 处理 |
| --- | --- | --- |
| 提示缺少配置 | `.env` 是否存在 | 复制示例并修改字段 |
| 初始化拒绝非空目录 | 运行目录是否属于其他实例 | 选择新的空运行目录 |
| 提示镜像缺失 | 是否执行过 `Prepare` | 在维护时执行 `Prepare` |
| 本地入口无法连接 | Docker 和容器是否运行 | 检查 Docker Desktop 与容器日志 |
| 外部存储不可用 | OpenList 用户和 `/baidu` 挂载 | 在 OpenList 中验证读写 |
| 本地校验返回 401 | 本地账号凭据是否失效 | 执行 `SaveCredential` |
| 本地校验返回 404 | 外部存储名是否匹配远端路径 | 检查 `CLIENT_REMOTE_PATH` |
| 提示尚未配对 | 专用配置是否保存账号 | 显式执行 `Pair` |
| 提示账号不在本机 | 客户端是否连接到其他服务器 | 检查专用配置，不要覆盖其他账号 |
| 默认客户端已有账号 | 是否运行了其他配置 | 自行退出该实例，再启动本项目 |
| 文件存在但不显示 | 上游客户端是否排除该文件 | 检查客户端排除规则 |
| 空文件读取返回 409 | 百度端标记是否被直接修改 | 保留状态，检查已知备份 |
| 哨兵存在但数据库缺失 | 适配器状态是否不完整 | 恢复同一时间点的完整运行目录 |
| 重命名后路径被阻止 | 是否存在未确认操作 | 保留状态，核对上游操作结果 |

## 容器日志

在仓库根目录执行：

```powershell
docker compose --env-file .env logs --tail 100 nextcloud nextcloud-gateway empty-codec openlist
```

日志可能包含路径或账户信息。发布日志前，删除个人信息和凭据。

不要将 `.env`、运行目录、完整客户端配置或数据库附加到公开问题中。

## 不要使用的修复方法

- 不要删除空文件登记来绕过校验。
- 不要把全部用户目录上传到问题附件。
- 不要把服务端口改为公网监听来解决本机连接问题。
- 不要删除运行目录后重新执行初始化。
- 不要强制终止尚在传输的客户端。

如果无法确认状态，先停止变更并保留现场。
